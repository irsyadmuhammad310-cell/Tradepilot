Install and open offline

Extract the release ZIP. For desktop use, run python -m http.server 8000 --bind 127.0.0.1 --directory dist from the folder containing dist. On Windows you can use py in place of python. Open http://127.0.0.1:8000/ in your browser. Keep using the same address, port and browser profile to access the same account.

For your phone, serve the contents of dist/ from a stable HTTPS address. With GitHub Pages, copy everything inside dist/ into the root of the publishing branch, with index.html directly at the root. In repository Settings → Pages choose Deploy from a branch, select that branch and /(root), and save. Open the published Pages address. Only application code belongs in the publishing folder. GitHub Pages documentation

Open the app online once and check More → Settings & data → Offline workspace. Wait for “Available offline.” In Chrome or Edge use Installation options or the browser’s Install app command. On iPhone open the HTTPS address in Safari, use Share → Add to Home Screen, enable Open as Web App if shown, then tap Add. Open the installed app once online before testing it in airplane mode. An extracted HTML file opened directly from Downloads cannot register the service worker. Apple’s installation guide

The cache includes the application and this guide. IndexedDB holds the account. Browser profiles, devices, and sometimes installed-app contexts have separate storage. Use JSON backup and restore to move a journal between them.

Record a trade

  1. Use Journal → Strategy versions to record a setup, its version and its execution rules. Each new version gets its own permanent ID.
  2. Plan new trade saves entry, initial stop, target, fees, slippage, direction, contract, and checklist evidence. Select the planned exchange date and MYT time. Save before execution to establish contemporaneous evidence. A plan creates no settlement. You can also save a draft or cancel a plan.
  3. Open a plan and select Record execution to enter actual entry and exit times and prices. If the initial plan was saved after the actual entry, the closed record is labelled retrospective. The original plan survives edits.
  4. Log completed trade opens quick entry. The defaults are one FCPO contract and RM50 round-trip fees. Open Advanced journal fields for costs, fills, screenshots, notes, compliance and reflection. A trade with an unknown historical delivery month can be recorded. A reviewed trade requires a written reflection and lesson.
  5. Use the top dataset selector before entering practice trades. Live, simulated and backtested results are separate. Each dataset has its own statistics. Only live trades settle into the capital ledger.

Times are entered in Malaysia time (UTC+8) and stored as UTC instants plus the exchange timezone. Confirm the exchange dates against the contract note, especially for night sessions and holidays. The app has no exchange holiday feed. Weeks run Monday through Sunday. With equal execution timestamps, new records use their original entry order to break ties. Fill rows use whole contract quantities and whole FCPO price points. Give one fill per line, e.g. entry | 4000 | 1 | 2026-11-18T10:35 followed by exit | 4010 | 1 | 2026-11-18T11:05. The execution pair in this example yields RM200 net after RM50 fees. Actual fills determine weighted prices and realised P/L. Enter total round-trip fees once, plus separately itemised costs.

Search and filter history by result, contract, strategy, status or dataset. Opening a record shows its ID, evidence, images, prior versions and acknowledgments. Edits require a reason. Moving a trade to the recovery bin removes its settlement from totals. Select Recovery bin in the journal to restore it.

Read the risk monitor

The per-trade warning is the lower of 3% of the applicable recorded balance and RM400, rounded down to the nearest sen with a zero floor. RM10,000 gives RM300. Planned risk includes absolute entry-to-stop distance × RM25 × quantity, estimated round-trip fees and the configured slippage allowance. Net planned reward deducts those allowances from gross target reward. The initial saved plan supplies historical R:R and risk comparisons. Edited proposals show their revised projected risk.

Daily and weekly warnings start at RM450 and RM750 of net realised loss. The monitor also reports total losing-trade amounts before winners offset losses. Three losses trigger a streak warning. An exactly net-zero trade carries the streak forward. A net winner resets it. The projection on a plan models the effect of its stop on the period’s existing results.

Warnings require acknowledgment and a written reason. An oversized stop suggests reviewing size or skipping the trade. The technical stop remains the trader’s decision. Holdings that overlap in saved execution intervals count toward the one-contract rule. Equal timestamps alone do not establish overlap between the exit of one trade and entry of another. If the time is uncertain, check the contract note. The overnight check uses the recorded entry/exit dates in Malaysia time and the explicit overnight flag. There is no live position or margin feed.

Capital and reconciliation

Recorded Account Balance — Not Live Brokerage Equity starts at RM10,000. Funding, withdrawals, signed adjustments and net realised settlements determine the current recorded balance. Correct the starting amount through audited configuration. The default full margin reference is RM8,000, with 25% payable intraday (RM2,000). These are editable broker assumptions.

Open Capital ledger to enter a deposit, withdrawal, broker adjustment, or non-trading adjustment. Enter withdrawals as positive amounts. Record cash corrections as clearly described offsetting entries. Each live completed trade generates one settlement keyed to the trade ID, including costs exactly once.

For a monthly statement, select Reconcile. Enter its closing exchange date, balance type, amount and optional reference. Compare the realised cash balance through that date. Equity and available funds can include other items, so they retain the status Not Reconciled. The comparison stores a snapshot and updates the current comparison after historical corrections. Enter any justified adjustment separately.

Performance and discipline

Select a date range and dataset. Monthly net P/L on Home always refers to the current exchange month. Win rate uses net winners divided by all completed trades, including net-zero trades. Profit factor uses net winning amounts divided by absolute net losing amounts. Blank denominators appear as unavailable. Rolling 20- and 50-trade windows use completed trades in the selected period. Session groups are descriptive MYT time buckets (morning 06:00–12:59, afternoon 13:00–18:59, otherwise evening).

Trading return chains each settlement’s return on the account balance immediately before that settlement. Funding and non-trade adjustments change the denominator for subsequent trades. Maximum RM drawdown compares trading-only cumulative P/L to its prior high. Percentage drawdown measures decline from the compounded return index’s high. A nonpositive pre-settlement balance makes percentage results unavailable. Simulated and backtested curves use the configured opening capital as a modelling baseline.

Wednesday reviews and AI Coach

Start a weekly review from Home. Select the period, read its saved-trade statistics, then write your reflection and one measurable objective. Monthly, quarterly and annual reviews appear in the same archive. Use Development tracker for the 50-, 100- and 150-trade assessments, the one-year live review and capital readiness. The 100-trade evaluation uses one strategy version. A count makes a review eligible. Completing the assessment requires a written review.

In AI Coach, choose weekly, monthly or selected-trade evidence. Inspect the preview before copying, saving or downloading. Written notes are opt-in. Saved reports keep a snapshot, so subsequent journal edits leave the original report intact. To use ChatGPT, copy the report and paste it yourself. Local calculations and reports work offline.

Back up, restore and recover

  1. Open More → Settings & data → Download full JSON. Save the file somewhere separate from browser storage. The recorded date indicates a download request. Check that the file is actually present.
  2. Full JSON includes trades, plans, strategy versions, audit history, ledger inputs, reviews, reports, settings, and chart attachments. CSV is a readable history export, including dataset and recovery-bin status. Use JSON for restoration.
  3. Select Restore JSON and choose a backup. The app validates structure, IDs, financial inputs, references, audit history and the checksum on new backups. Compare the incoming balance and record counts. Confirm only if this is the account you intend to restore.
  4. Restoration atomically replaces the account after validation. A failed validation or write keeps the current account intact. Recover pre-restore account lets you return to the previous local snapshot. Each successful replacement updates that single recovery slot.

Storage limits depend on the browser and available space. Full JSON supports up to 80 MiB. Each trade accepts up to four PNG, JPEG or WebP screenshots, up to 2 MiB each. Attachment bodies are deduplicated across audit snapshots. A checksum helps detect accidental changes. Backups contain readable personal information. Protect exported files and your device. Clearing site data or losing a device can erase the journal.

In-app reminders work whenever the app is open. Optional device notifications depend on browser support and permission and are checked when the app opens or returns to the foreground. There is no closed-app alarm service. If another tab changes the account, reopen a stale form before saving.
